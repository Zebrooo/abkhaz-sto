# Поиск по услугам в «Записать клиента» + починка обрезанных полей

Дата: 2026-09-22. Статус: одобрено (вариант «клиентский фильтр над списком»).

## Задача

На экране «Записать клиента» (`src/app/(app)/kalendar/novaya/page.tsx`) услуг уже 74,
плоский список без поиска — нужную не найти. Экран один и тот же для владельца СТО
и для админа сайта (вход через витрину), так что одна правка закрывает оба случая.

Вторая проблема: на вебе правая колонка формы обрезается краем карточки —
поля «Телефон», «VIN», «Комментарий» уезжают за границу `.nb-box` (overflow: hidden).

## Решение

### Поиск

Клиентский компонент `ServicePick` (по образцу `ClientPick`): поле «Найти услугу»
над списком, при вводе мгновенно фильтрует пункты по названию. Сервер, как и сейчас,
считает список подходящих услуг и ссылки (`href({ s })`) — компонент получает готовые
пункты `{ listingId, title, sub, href, selected }` и только скрывает неподходящие.
Состояние шага остаётся в URL, серверная архитектура не меняется.

- Совпадение: подстрока без учёта регистра, ё = е. Чистая функция
  `matchesService(title, query)` в `src/lib/booking-form.ts`, покрыта тестами.
- Поле поиска показываем от 8 услуг — короткому списку оно не нужно.
- Пусто по запросу — подсказка «Ничего не нашлось» с кнопкой сброса.
- Подсказки «N услуг не влезают в окно — показать все» остаются серверными,
  под списком, и видны независимо от фильтра.
- Без автофокуса: на телефоне клавиатура не должна выскакивать сама.

### Вёрстка

На десктопе `.nb-fields` — грид `1fr 1fr`; у грид-колонок min-width: auto, и строка
«Госномер + VIN» распирает вторую колонку за край карточки. Чиним:
`grid-template-columns: minmax(0, 1fr) minmax(0, 1fr)` плюс `min-width: 0`
грид-детям `.nb-fields`.

## Не делаем (YAGNI)

Категории услуг, серверный `?q=`, комбобокс вместо списка, поиск по цене.

## Проверка

Vitest на `matchesService`; визуально — дев-сервер, десктоп и мобильная ширина:
поиск фильтрует, поля не обрезаются.
